# DeepSeek、缓存和定时任务：先看懂这些坑

[返回入门说明](../README.md)。这是使用提醒，不是“所有问题自动修好”的承诺。核对日期：2026-10-20。

补充：本次又核对了 Gemini / Antigravity 里的历史排查和当时的工具日志，确认还有遗漏。见[切换账号踩坑复核清单](switching-errors.md)，重点是定时任务格式错误、自动压缩报错、反复重连，以及不能照搬的旧“修复方案”。公开文档不包含私人聊天、截图、账号名称或内部服务地址。

## 1. Codex 不只可以用 GPT，但不是“什么模型都能接”

可以把 Codex 理解成工作台，背后回答问题的模型可以换。DeepSeek 官方已经提供 [Codex 接入说明](https://api-docs.deepseek.com/quick_start/agent_integrations/codex/)，并说明支持 Codex 所需的 [Responses 接口](https://api-docs.deepseek.com/guides/responses_api/)。

这不意味着其他任意服务也能直接用。要确认三个东西：API 地址、准确模型名，以及它是否真的适配 Codex。网页聊天能用、地址填对、模型选择框里有名字，都不等于工具执行和定时任务已通过测试。

本工具生成的是通用基础模型列表，不会自动照搬 DeepSeek 官方的全部模型设置。图像、联网、上下文长度、可选思考等级等可能需要额外适配。初次接入有疑问，先对照官方教程；切勿在不备份的情况下，让多个工具轮流改同一份配置。

## 2. 为什么聊天能用，定时任务却可能失败？

把它想成两张单独的“预约单”：

- 你刚开的聊天，用当前选好的配置。
- 已保存的定时任务，可能写着自己的模型和思考档位；跟在旧聊天里的提醒，还要接着读取旧消息。

因此，**切完模型后，不能直接认定所有预约单也跟着改好了**。本地确实存在单独指定模型的任务。此外，本次在历史排查里找回了定时任务经 DeepSeek 返回 `422`、提示缺少 `call_id` 的日志；这次故障与旧记录格式有关，不能把所有自动化错误都归因于模型名或 DeepSeek。具体看[错误对照](switching-errors.md)。

建议这样验证：

1. 切换前，找出接下来会运行的重要任务。必要时在应用里暂停高风险任务，避免切换到一半就触发；本工具不会代你暂停或修改它们。
2. 切换并重启后，先新开普通聊天，问一个不涉及公司资料的简单问题。
3. 再检查任务里保存的模型是否仍被当前服务支持。需要改时在应用里修改，不要直接批量替换配置文件。
4. 对无外部写入的任务，先做一次小范围手动测试。会发消息、改数据、跑付费采集的任务，不能为了测试随便重跑。
5. 看实际结果：有没有生成预期文件/数据、有没有重复执行，不能只看任务显示“已开始”或“已完成”。

任务使用本地文件时，电脑和应用的运行条件仍然重要；换模型不会把本地定时任务变成自动托管的云任务。当前规则见[官方定时任务说明](https://developers.openai.com/codex/app/automations/)。

## 3. 为什么旧聊天报错，新聊天却可能正常？

不同模型服务对“聊天记录的格式”要求不完全相同。旧工具结果、旧思考记录，可能不符合后来服务的检查规则。

历史工具日志确认出现过：工具结果缺少关联编号、消息编号前缀不被接受、部分思考记录格式不兼容。旧修复代码也保留过对应分支。但“当时发生过”不代表今天每个版本仍有同样限制，更不能证明所有自动化都遇到同一个原因。

看到 `400`、`call_id`、`function_call_output`、`fco_`、`reasoning` 等字样时：

- 保留报错，先用新聊天做无敏感内容的小测试，区分“Key/模型根本不能用”还是“这段旧记录不能继续”。
- 新聊天正常，优先带一份简短交接继续工作，原聊天留着。
- 不要直接删除旧消息或把工具输出伪装成用户发言。需要迁移历史时，应单独备份、逐项验证，不在切账号时偷偷做。

公开版 `doctor` 默认只检查侧边栏索引；`doctor --apply` 也只改已知索引。**它不会清洗聊天内容，不保证修复这些格式错误。**

尤其注意：旧记录修复本身也可能引入新的格式问题。历史上确实出现过“为了修缺少关联编号而改了记录类型，但没同步改消息编号，后来切回官方账号又报错”的连锁情况。因此不把旧修复器整套打包为公开版的默认自动操作。

## 4. “Content Exists Risk”是什么？

历史排查对话中确实出现过这个服务端拒绝提示，但没有确认具体触发内容。它不能据此归结为网络绕路、API Key 错误或模型完全不可用。

不要无限重试，也不要为了绕过平台检查去变造内容。先确认没有误传私人/敏感资料，再按服务商规则排查；向支持人员提供必要的错误信息，不把完整聊天和 Key 公开出去。

## 5. 缓存命中，用大白话怎么理解？

模型每次可能都要读前面的材料。服务器如果能复用之前读过的开头部分，就叫“缓存命中”。

- 它主要节省重复输入的处理，不是照抄上次答案，也不是这次不用付钱。
- DeepSeek 的相关缓存由服务端自动管理，本工具没有“开启必中”的按钮。
- 改了前面的材料、换模型或上下文内容变化，都不应再假定会保持原来的命中情况；不能承诺长期固定比例。
- 有中转时，要看中转有没有返回真实统计、怎么收钱，不能照搬 DeepSeek 官网价格。
- 本工具当前不读取真实请求的用量，也没有缓存监控面板。状态里的“配置成功”不是缓存命中证明。

客户端在后台怎样拼接材料（有时叫 harness）、你是否改了前面的内容、服务端的缓存规则都会影响结果。不能根据某一天的截图就断言“Codex 比 Claude 或 Gemini 更能命中缓存”，更不能承诺一直保持某个比例。正常任务可连续处理，但不要为了命中率硬撑已经卡住或报错的长聊天；必要时先做交接再开新聊天。

想核对数字，可查看服务商实际请求记录（如果有）或响应中的用量。Responses 接口的字段是：

```text
输入总量：usage.input_tokens
其中命中缓存：usage.input_tokens_details.cached_tokens
输入缓存命中率 = 命中缓存 ÷ 输入总量
```

例如，输入 10,000 个 token（可粗略理解为文字计量单位），其中 8,000 个命中，输入缓存命中率就是 80%；**不是总费用打两折**，输出、其他输入和服务商计价还要分别算。输入总量为 0 或没有返回统计时，记为“无法计算”，不要硬当 0% 或 100%。

Chat Completions（另一种 API 格式）用 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`；不要跟 Responses 的字段混用。说明依据：[DeepSeek Responses 用量说明](https://api-docs.deepseek.com/guides/responses_api/)、[缓存规则](https://api-docs.deepseek.com/guides/kv_cache/)。价格会变，这里不写死金额。

## 6. 联网、图片、插件也要分开验收

“模型能回答”不等于“原来的工具全都能用”。服务端自带的搜索，与 Codex 客户端连接的插件/本地工具，不是一回事。DeepSeek 对部分功能有单独支持范围，具体看[兼容说明](https://api-docs.deepseek.com/guides/responses_api/)。

日常任务需要读图片、联网、调用某个插件时，逐项做小测试；不能因为一项失败就说所有工具都不能用，也不能因为聊天成功就说全部兼容。

另外，地址写着 DeepSeek 官网不代表一定“国内直连”：系统代理仍可能让流量绕路。本工具不修改代理规则，连接慢时先检查实际网络路径。

## 7. 最常见的其他问题

| 现象 | 简单理解 | 先怎么办 |
| --- | --- | --- |
| Key 提示没配好 | 刚开的程序仍拿着旧设置 | 完全重开桌面端和终端，确认切换命令成功 |
| 重启 Mac 后 API 不能用 | 系统没有保留本次提供给应用的 Key 环境 | 再运行一次对应的切换命令 |
| 没有目标模型可选 | 模型选择列表没有准备好，或没重启 | 参考[模型列表设置](advanced.md#4-中转的模型选择框包括-gpt-61-sol)，再重启 |
| 模型不存在 / 无权使用 | 提供方没有该型号，或这个 Key 没权限 | 问提供方，不能只改本地名字“解锁” |
| 旧对话从侧边栏消失 | 可能是显示索引，也可能是项目/账号等其他原因 | 不删历史，先运行只读 doctor；它只覆盖有限索引 |
| 反复显示重连 1/5～5/5 | 可能是网络、连接方式、网关或上游服务问题 | 看[重连排查](switching-errors.md#3-一直重连不等于一定是账号坏了)，不能只凭次数下结论 |
| 压缩已中断 / 整理历史时报错 | 可能是旧消息或旧工具记录的格式问题 | 先保留原聊天并做交接，不要直接删除历史或随意清缓存 |
| 429 / 余额不足 | 服务端限制或账户计费问题 | 核对余额和用量，别无上限重试 |
| Python / codex 找不到 | 必要工具没装好，或终端找不到安装位置 | 先确认版本命令能用，不要重装整个桌面端 |
| 更新仓库后短命令还是旧的 | 可选安装会复制一份工具，不会随 git pull 自动更新 | 暂时从新仓库执行；备份旧入口后再更新安装 |
| 想换回原来 | 当前服务不适合这项工作，或设置出了问题 | 完全退出后切回原账号；[备份恢复](advanced.md#6-回滚历史与边界)另有说明 |

## 8. 数据和费用最后再确认一次

切换后发给模型的聊天、代码和工具结果，会交给所选服务处理。公司代码、客户资料、私人记录，先确认能否发给它。Key、登录资料和备份留在自己的电脑，不能随求助截图、日志或仓库发给别人。

本项目自动测试只使用虚构数据，模型列表也只做本地读取。没有在这里宣称已完成你的 DeepSeek 真实账号调用、缓存比例测量或所有定时任务验收。
